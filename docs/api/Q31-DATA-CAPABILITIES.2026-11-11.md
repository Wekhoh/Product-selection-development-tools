# Q31 数据能力核查

核查日期：2026-11-11。仅使用当前已暴露工具的声明和官方公开文档；没有调用商品、市场、额度探测或其他业务端点，没有读取凭证或真实请求账本。这是技术研究候选，实际返回、账户权限、完整率、耗时及批量能力尚未验收。业务定义和评分映射由选品开发席与主人确定。

## 父体销量、词数和曝光

| 需求 | 已声明的能力和候选字段 | 必须保留的边界 |
| --- | --- | --- |
| 卖家精灵父、子体月销量 | `asin_sales_trend` 的 `salesTrendPoints[]` 提供 `month`、`parentUnitSales`、`childUnitSales`；销售额另列。商品对象有 `parent`、`variationList`。 | 采用件数时不要取销售额。按父体去重后每月只计一次父体销量；不能再叠加子体或同父体其他返回行。历史变体归属、数据精度及实际覆盖期未获保证。来源：[销量趋势文档](https://open.sellersprite.com/api/61)。 |
| SIF 父、子体月销量 | 当前原生 `mcp__sif__ops_get_asin_sales_trend`：月份轴 `boughtHistoryDates[]`；变体 `chars[].boughtList[]` 是对象数组；父体 `pasinBoughtHistory.boughtList[]` 是整数数组。 | 按月份轴同下标取值，空值表示缺数据。近 30 天字段 `boughtInPastMonth`、`pasinBoughtInPastMonth` 是前台档位字符串，不是精确销量。原生接口没有时间窗参数，按实际返回月份说明覆盖。依据：本次工具声明。 |
| 卖家精灵自然、广告词数量 | `traffic_keyword_stat`：`keywords` 总词数、`ranks` 自然词数、`ads` 广告词数、`badgeCount` 分类型数量、`calcTime` 计算时间。 | 这是词数，不是曝光占比。同一词可被不同渠道覆盖，不能把自然词和广告词直接相加作为去重总词数。文档未给该接口父体汇总开关，不能假定输入一个子体就获得整个父体的去重词集。来源：[流量词统计](https://open.sellersprite.com/api/13)。 |
| 卖家精灵关键词曝光 | `traffic_keyword` 返回 `trafficPercentage`、`naturalRatio`、`adRatio`，并有自然/广告排名及其更新时间。 | 前者是词对商品的曝光贡献，不能与词内自然/广告比例混用；均不是订单占比。默认近 30 天，也可查历史自然月。官方限制最多查询 2,000 条，翻完可取页不必然得到完整词集。来源：[关键词反查](https://open.sellersprite.com/api/14)。 |
| SIF 变体词数 | 原生 `ops_get_listing_keyword_distribution`：默认 `showType=1`；`asins[]` 下的 `total`、`natural`、`ad` 等是词数。顶层 `total` 是 ASIN 行数。 | `ad`、`brandVedio`、`spRec` 已是去重合计，不能再由分项相加。跨变体的唯一词数需要同周期词集取并集，单有各变体计数无法算出。声明还列出 `showType=2` 曝光分数模式，与默认词数模式须隔离，返回形状尚未验证。依据：本次工具声明。 |
| SIF 自然/广告曝光结构 | 原生 `ops_get_listing_traffic_overview`：`isListingSearch=true` 为 Listing 汇总，`false` 为单 ASIN；渠道节点有 `score`、`ratio`。 | `ratio` 是相对于上层节点的 0–1 比例，不保证每层分母都是总曝光。它反映供应商的曝光测量，不能当实际点击、订单或支出。缺渠道是未知。依据：本次工具声明；曝光解释见 [SIF 官方教程 §3.1](https://blog.sif.com/article/bl37ebc3d60b1649b2a64fbf4d14eae39f/%E5%9B%BE%E6%96%87%E6%95%99%E7%A8%8B%EF%BC%9A%E5%8F%8D%E6%9F%A5%E6%B5%81%E9%87%8F%E8%AF%8D)。 |

SIF 的上述词数/曝光周期允许近若干天、周或月；当前声明要求周参数使用周日、月参数使用月首日期，近 7/30 天是滚动窗口。不要把这些窗口与卖家精灵的自然月无条件对齐。保存请求周期、实际数据截止日和缺口；公开教程中的历史覆盖起点也不是本账户或每个 ASIN 的覆盖保证。

父体销量与父体曝光必须分别核实聚合范围。当前 SIF 流量趋势声明说明汇总变体集来自会变化的变体库，因此当前父子关系不能证明历史月份的成员关系。关键词去重也不能靠词数相加；列表被截断时只能报告已覆盖部分。

SIF 两个已暴露入口存在声明差异：原生销量工具是上述并行月序列；`mcp__codex_apps__sif_mcp_ops_get_asin_sales_trend` 则描述 `list[].months[]`，并接受时间参数。后续必须固定具体工具名称，不能拼接两套说明实现一个解析器。此次没有付费探测两者。

另须区分商品关联覆盖与搜索曝光。卖家精灵关联 ASIN 数量表示出现过关联位置的商品范围，不是访问人数或订单数量；相关百分比不能移作搜索曝光或销售份额。来源：[关联流量官方说明](https://www.sellersprite.com/cn/v3/knowledge/feature/relation-keyword-for-beginners)。

## 已知商品历史与历史榜单全集

| 来源 | 已声明的历史能力 | 不能承诺的能力 |
| --- | --- | --- |
| 卖家精灵 `keepa_info` | 单 ASIN 的 `bsr`、`subSalesRank`、排名节点变动、评分数和星级历史；可给毫秒起止时间，并用 `dailyLatest` 只留每日末条。 | 需要先知道 ASIN。请求时间窗不保证数据齐全；每日末条可能漏掉日内短暂进榜。它不是按类目枚举历次前 100 成员的接口。来源：[商品历史文档](https://open.sellersprite.com/api/22)。 |
| SIF 原生 `ops_get_asin_traffic_trend` | 日粒度声明有 `bsr`、`subBsr`、`review`、`star`、`catId`，以及跟踪、新鲜度与末点完整性字段；周/月粒度不返回排名/评价等数据。 | 仍以已知 ASIN 为入口。`listingSearch` 的流量汇总开关不能证明所有排名/评价字段也按父体合并；`review` 的评分数/文字评论口径仍待核实。依据：本次工具声明。 |
| 卖家精灵 `competitor_lookup` | 月份、类目及分页查询，`variation=Y` 不含变体、`N` 含变体。官方字段表把父体月销量与子体近 30 日销量分别列示。 | 月度筛选不是逐次历史榜单档案，也不保证找出所有短暂进榜者。去变体选项不能证明历史父体归并完整。来源：[查竞品文档](https://open.sellersprite.com/api/1)。 |

**结论：基于此次已检查的接口，不能保证找全指定类目历史上所有曾进前 100、后来退出的新品。** 这是已证实能力的边界，不是宣称市场上不存在其他历史档案产品。已知 ASIN 的历史曲线无法补出从未被发现的 ASIN。

工程建议：只保存“首次观察到进前 100”的时间和来源，字段可沿用 `first_seen_in_top100_at`。同站点、同节点、同返回主体的有效排名才可连成轨迹；空值、负值、类别变化和未采集不等于退榜。覆盖开始即在榜时，更早首次入榜未知。由此形成的样本统计不能称为整个市场的新品成功率。未来增加定期采样也只能改善观察覆盖，不能补齐过去全集。

## 首次观察进榜时的评分数量

卖家精灵 `keepa_info` 官方字段表把 `reviews` 定义为**评分数趋势**，把 `rating` 定义为星级；趋势点使用 `timePoint`、`value`。这与销量趋势接口快照里的 `ratings`（评分数）、`reviews`（评论数）不同，映射必须包含来源接口，不能仅凭英文名称统一。该历史接口另有 `asin`、`dataAsin`、`parentAsin`：请求对象与实际返回历史对象可能不同。[历史字段](https://open.sellersprite.com/api/22)、[快照字段](https://open.sellersprite.com/api/61)。

建议的证据组合是：指定节点的首次有效在榜观测时间、同一返回主体的评分数观测时间和值、父体归属证据及实际覆盖说明。以下限制必须随结果保留：

- 同一天不等于同一时刻；排名和评分数可能异步采样。若只有附近评分观测，只能标为邻近观测，记录时间差；不能冒充入榜瞬间数值。允许多大时间差尚未批准。
- 每日末条会丢失当天更早状态。关掉该选项也不保证供应商覆盖每次变化。
- 当前评分数不能回填历史；空值、负值或缺失不能填零，也不凭插值生成入榜评价。
- 父体销量可用不代表历史父体评分已齐全。若评分主体、合并评价或历史变体归属未明，应保留口径冲突，不能与父体销量直接组成确定评分。
- 首次观察进榜与真实首次进榜不同；本次不能承诺每个新品都有可用的首次进榜评分数。

以上采样与对齐处理是依据数据能力提出的工程建议，未确定新品门槛、评分曲线、缺证处理或采购预算。下一步只需由选品开发席把这些已知能力和未知项带入业务设计；实际小样本验证须在业务范围与调用授权明确后单独验收。
