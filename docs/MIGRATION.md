# Selective migration

This project keeps useful product intent and evidence while independently choosing its implementation. A copied file is not an adopted component.

## Asset decisions

| Asset | Treatment | Reason / acceptance |
| --- | --- | --- |
| Confirmed goals, trial preferences, conditions, and open questions | Curated into public product/design documents | A new chat must understand the project without an old task board |
| Raw design discussion and historical research evidence | Local provenance index and selected recovery snapshots | Preserve traceability without publishing original conversations or business data |
| Former selection package: 53 Python files | Inventoried for selective reuse, not installed or imported | The package still depends on its previous environment, quota, sources, state and publication planes |
| Evidence-grade / unknown-value utilities | Potential reuse | Verify semantics and standalone inputs before adopting code |
| Economics and fee calculations | Review and adapt against agreed inputs | Historical payment-fee defaults are not established current fees; keep unknowns explicit |
| Old discovery, gates, scoring and seed lists | Redesign against the current product decisions | Executable historical rules do not establish the new discovery strategy or scoring design |
| Provider and Agent integrations | Separate integration handoff | Credentials, budget reservations, ambiguous requests and actual capability acceptance must be reconciled |
| Old publisher, store-operation ledgers, approvals, schedulers and full-store control | Excluded from the new runtime | These belong to the retired operating architecture |
| Unrelated useful workflows and large upstream resource collections | Later work | No new repositories or bulk imports in this scope |

## Independence acceptance

A releasable application must install and exercise the agreed offline path from a clean checkout without the old repository, its Python environment, caches, absolute paths, service processes, or task schedules. The later live stage must separately verify configured sources and cost/recovery controls. No completed runtime acceptance is claimed yet.

For every adopted code batch, retain source provenance and license notices, examine dependencies and changed assumptions, run focused behavior/integration checks, and review the files actually being published. Do not transfer private Git history.

## Cost and privacy

Use standard GitHub-hosted runners for public CI; larger runners and external services are separate costs. Add CI for actual code checks, with no live provider requests or scheduled research. GitHub's current billing reference: https://docs.github.com/en/billing/concepts/product-billing/github-actions

Local copies of private evidence are excluded from Git and never become test fixtures without explicit sanitization. Existing originals remain intact. Moving folders does not authorize resetting a budget or reissuing a request with an unknown outcome.
