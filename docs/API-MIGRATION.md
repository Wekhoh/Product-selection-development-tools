## Spending, recovery, and legacy reconciliation guardrails

- **Budget admission and settlement.** The account policy requires a verified platform hard limit, auto-recharge off and a monthly limit of at most 20,000 cents. Each billable submission reserves integer cents under `BEGIN IMMEDIATE`. Uncapped search reserves an estimated 25 searches by default, plus estimated input and maximum output token charges. Actual usage can exceed that estimate. The ledger records verified usage in full and checks remaining funds before every further admission. Search actions cost $0.01 per call plus token usage. Page opens and in-page finds are counted for monitoring. An explicit provider search count takes precedence. Historical actionless items use the legacy search charge. A future unknown action without an authoritative count leaves the charge unresolved. [Web search](https://developers.openai.com/api/docs/guides/tools-web-search) · [API pricing](https://developers.openai.com/api/docs/pricing)
- **Recovery.** Billable POSTs have zero retries. A queued background acknowledgment binds the provider ID in SQLite before polling. Idempotent GETs retry transient failures. A known ID can be polled after restart. Cancellation is an explicit operator action. Missing usage keeps the hold. The default same-month pending buffer is zero. `openai-reconcile --same-month-pending-buffer-cents 1000` permits up to $10 of qualifying unresolved current-month holds, while preserving every reserved cent in admission accounting. The accepted range is 0–2,000 cents. Cross-month unresolved work, active submissions and required cleanup keep their fences. [Background mode](https://developers.openai.com/api/docs/guides/background) · [Cancel a response](https://developers.openai.com/api/reference/resources/responses/methods/cancel)
- **Read-only legacy `budget.sqlite3` reconciliation:** Before enabling live paid API calls (`legacy_reconciled: true`), `inspectLegacyAutopilotBudget` inspects the canonical legacy `budget.sqlite3` strictly read-only (`?immutable=1` or private snapshot, `query_only = ON`, never writing or creating files on the legacy path) and `reconcileLegacySummary` / `openai-reconcile --legacy-budget` transactionally imports monthly carryover reservations while refusing activation if any unresolved/unknown legacy hold exists. Keep `reserved_cents`, `usage_cost_micros`, and `posted_billed_cents` distinct; never record `0` for an unknown outcome.
- **Pre-activation key rotation, `$500 -> $200` subscription transition & `Agent Builder` sunset:** Before toggling `enabled: true` for any live paid OpenAI HTTP call, revoke/rotate any API key previously shared in chat and store the replacement solely in git-ignored `.local/` credentials. During the November `$500` Pro cycle, verify `Auto-recharge OFF` and check `Billing -> Credit grants` for any month-end expiring credit grant (`Codex CLI` `Astra` supports `service_tier="ultrafast"` while on Pro-500, falling back automatically to standard tier after next month's transition to steady-state `$200/month` Pro + `$200` non-rollover API credit cap). Visual `Agent Builder` is intentionally avoided due to its `2026-11-30` sunset.
- **GPT-6.2 HTTP wire & prompt-caching maintenance rules:** For any future `gpt-6.2-*` (`gpt-6.2-sol` rare escalation) `/v1/responses` maintenance, place reusable static instructions inside the first `developer` message of `input` (GPT-6.2 appends top-level `instructions` after `input`, which breaks prefix caching), avoid mid-chain prefix edits or model switches (which drop encrypted reasoning state), omit unsupported `temperature` / `top_p` / `logprobs` and `service_tier: "flex"`, and prefer `prompt_cache_options: { ttl: "30m" }` where supported.
